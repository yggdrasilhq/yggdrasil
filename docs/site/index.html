yggdrasil

One config file. A bootable, self-healing ZFS+LXC Debian spine.

Most infrastructure starts as a careful manual setup and decays into tribal knowledge. yggdrasil goes the other way: your server's entire OS layer — ZFS root, boot chain, LXC containers, recovery image — is described by one private config file and built into a live ISO by a public, reviewable generator.

And because the ISO is the machine, the stick that built it is the stick that resurrects it. If a kernel update dies at 2am, ZFSBootMenu boots the previous kernel — with wifi and ssh in the recovery image itself, so you fix the host from your desk instead of the desk the host sits on.

Principles

  • Site-private, repo-public. One ygg.local.toml carries your proxy, keys, pools and network. The repo carries the machinery and never your values.
  • Promises are verified. If a boot parameter or package list promises something, the smoke tests check the built image actually contains it.
  • Recovery is a feature, not an afterthought. The ZBM boot image ships with wifi, ssh and the previous kernel. Silence is the design: recovery layers never touch the boot screen.
  • Agent-native. An agent with shell access can build, test and ship the ISO end to end — the skill is in the repo.

Quickstart

git clone https://github.com/yggdrasilhq/yggdrasil && cd yggdrasil
cp ygg.example.toml ygg.local.toml   # your site values
sudo ./mkconfig.sh --profile both    # builds server + kde ISOs
./tests/smoke/run.sh                 # gates the ship
