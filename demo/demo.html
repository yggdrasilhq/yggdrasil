Operator Journey

What the operator actually does.

The product is intentionally linear. Each stage answers one question, and every answer becomes visible proof before the operator moves to the next step.

1

Choose the machine intent.

The flow opens on outcome, not checkboxes. The operator picks the machine they are trying to make real, and the app uses that to set the tone for everything that follows.

Preset cards make the product posture readable at a glance: NAS, Dev Host, Personal Workstation, or Recovery Anchor.
The selected intent is spotlighted while alternative intents remain visible, keeping the decision explicit and reversible.
2

Set the build posture.

Profile is where the operator decides whether the artifact lands as server, KDE, or the dual-profile build, then chooses whether the hardware path needs NVIDIA or LTS bias.

The main selection stays lightweight and fast, while the proof column clarifies what is recommended versus what is selected.
This keeps the posture legible without forcing the user into an infrastructure dashboard.
3

Name the machine and keep identity stable.

Personalization sets the setup name and hostname before anything is launched. This is where the artifact stops being generic and starts feeling like a concrete machine story.

The identity preview on the right turns the typed values into a saved machine narrative immediately.
Operators can see the setup slug, current stage, and artifact root without leaving the main studio.
4

Review the truthful inputs.

Review is the last quiet checkpoint before launch. The operator confirms artifacts path and optional repo root, while Shell Truth shows the emitted config or build plan in plain sight.

The main canvas stays editorial and calm while the right rail surfaces exact plan output.
This is the trust hinge: pretty enough for a guided product, exact enough for an operator.
5

Launch the artifact path.

Build distills the action down to one obvious move. The main panel summarizes mode, status, artifact target, and post-build handoff, while Shell Truth keeps the structured logs and manifest path ready on the right.

The tree on the left preserves prior setup history without becoming noisy, because repeated identical branches are pruned to the latest three releases.
The build CTA lives once, in context, instead of being duplicated across the shell.
6

Hand off the artifact cleanly.

Boot is the moment after the build. The operator either inspects the artifact, reveals it, or starts the next setup. The app makes this a completion moment, not a raw log dump.

This is where the product signals confidence: the software knows the artifact was created for a reason, not just as a file.
The journey can restart immediately without losing the history tree on the left.
Single-Surface Shell

The titlebar, rails, and background read as one environment. The main viewport is the only surface that intentionally floats.

Tree Retention

Repeated releases with the same preset, profile, and hardware branch are capped to the latest three, which keeps the historical tree useful instead of noisy.

Reusable YggUI Base

The same shell contract and theme rules are being hardened here as a portability harness for the broader Ygg UI stack.
